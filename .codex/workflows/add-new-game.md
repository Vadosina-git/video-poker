# $add-new-game — интеграция новой игры в агрегатор

Аргументы: название игры, URL стор-страницы или APK, при наличии bundle ID из запроса владельца.

Ты добавляешь новую игру в ЭТОТ проект-агрегатор (Video Poker — Classic
Edition). Игра станет игровым модулем `games/<id>/` с собственной
вкладкой в нижней карусели лобби и полной мета-обвязкой (общий баланс,
XP, квесты, магазин, BIG WIN, уведомления, локализация, remote config).

## Опрос владельца ПЕРЕД началом работы

До вскрытия референса задай пользователю (одним вопрос в чате (или штатный request_user_input, если доступен)) минимум:

1. **Как игра выглядит в лобби?** Представление НЕ обязано быть плашками —
   можно придумать иное. Готовые типы `cards.type` (GAME_INTEGRATION §3):
   - `game_variants` — карточка на каждый режим («режим = автомат», как
     домино: All Fives / Draw / Block);
   - `simple` — одна карточка «иконка + название + PLAY»;
   - свой формат — баннер, живое превью, промо-виджет и т.п. (новый
     `cards.type` + ветка в `lobby_manager._build_carousel` + описание
     в GAME_INTEGRATION §3).
2. **Что считается «раундом»** для ставки/квестов/XP (одна партия, один
   уровень, один заезд) — влияет на контракт `round_finished`.

Ответы фиксируй в манифесте и анализ-доках до старта порта.

## ⛔ ГЛАВНОЕ ПРАВИЛО

**НИ В КОЕМ СЛУЧАЕ НЕ НАЧИНАЙ ПИСАТЬ ИГРУ С НУЛЯ.**

Первый шаг ВСЕГДА — получить референс: найти и скачать подходящий APK
игры по переданному URL (стор-страница или прямая ссылка), разархивировать
и вытащить оттуда ассеты, скрипты, логику, баланс, звуки — всё как
референс. Для этого ОБЯЗАТЕЛЬНО вызови скилл **`$rip-godot`**, передав
ему название и URL из аргументов. Никакого «давай я сам придумаю
геймплей по описанию» — сначала вскрытие референса, потом порт.

Всё извлечённое — ТОЛЬКО референс: ассеты и код не используются as is
(лицензия!), они изучаются и пересоздаются/замещаются своими.

## Отличия от штатного $rip-godot (ОБЯЗАТЕЛЬНО учесть)

$rip-godot по умолчанию создаёт новый отдельный Godot-проект. Здесь —
НЕТ. Правила переопределения:

1. **Результат вскрытия** (распакованный APK, декомпилированные
   скрипты, ассеты) кладётся в референс-папку ВНЕ репозитория:
   `../_rips/<id>/`. В git агрегатора референс не попадает.
2. **Порт делается сразу внутрь агрегатора**: код и ассеты новой игры —
   в `games/<id>/` этого проекта (структура ниже). Переиспользуемая
   между будущими играми логика — в `libs/<домен>/`.
3. **Пропусти фазы rip-godot**: «каркас нового проекта», «монетизация/
   ATT», «сборка/экспорт-пресеты/деплой» — всё это уже есть в
   агрегаторе. Из rip-godot нужны только: получение APK → определение
   движка → вскрытие (GDRE Tools для Godot-игр) → анализ и документация
   геймдизайна → порт кор-лупа.
4. Если референс не на Godot (Unity/Flutter/native) — вскрытие всё
   равно делается (ассеты/баланс/UX доступны всегда), но код референса
   читается только как спецификация поведения.

## Куда и как встраивать (архитектура)

**ПЕРВЫМ ДЕЙСТВИЕМ прочитай `docs/GAME_INTEGRATION.md`** — там контракт,
формат манифеста, сейв-отсеки, квест-capabilities, чеклист приёмки.
Он — источник правды; если этот файл противоречит ему, прав GAME_INTEGRATION.

Структура нового модуля:

```
games/<id>/               # id — snake_case, короткий (напр. domino_3d)
  game.json               # манифест (формат — GAME_INTEGRATION §3)
  scenes/                 # entry-сцена + внутренние сцены игры
  scripts/                # геймплей-код модуля (строгая типизация!)
  assets/                 # ассеты игры (свои, не из APK as-is)
  configs/                # тюнинг игры (баланс, уровни) — JSON
```

Шаги интеграции (после вскрытия и анализа референса):

1. Создать `games/<id>/` + `game.json` (id = имя папки).
2. Реализовать контракт (GAME_INTEGRATION §4): `setup_game(launch)`,
   `round_finished(result)`, `back_to_lobby`, баланс через SaveManager,
   сейв-отсек `get_game_state("<id>")`.
3. Зарегистрировать модуль в `configs/games.json` (порядок = позиция
   вкладки в лобби).
4. Локализация: `name_key` вкладки + ВСЕ строки игры в
   `data/translations.json` во все 3 языка (en/ru/es), bulk — через
   python-сниппет из docs/CODEX_PROJECT_REFERENCE.md §8.
5. Иконка вкладки: `games/<id>/icon.svg` (или png), путь в манифест.
6. Квесты (опционально): `quest_capabilities` в манифесте; свои квесты
   в `configs/daily_quests.json` с фильтром `games: ["<id>"]`.
7. Remote config: ключ `games` уже оверрайдится (kill-switch bесплатно);
   новые тюнинг-конфиги игры при необходимости добавить в
   `ConfigManager._REMOTE_OVERRIDABLE` + `docs/REMOTE_CONFIG.md`.
8. Тест: минимум один headless-тест на кор-логику игры в `tests/`
   (чистые RefCounted-классы, без ссылок на автолоады — см.
   GAME_INTEGRATION §9).

## Приёмка

Прогнать чеклист из `docs/GAME_INTEGRATION.md` §8 полностью. Плюс:

- `./tests/run_all.sh` — только предварительная сводка. Runner подавляет код процесса через `|| true`, а маркер `Failed: 0` сам по себе не доказывает успех. До приёмки выполнить каждый разрешённый `tests/test_*.gd` отдельным процессом Godot, сохранить фактический exit code и полный лог, подтвердить ненулевое число assertions, отсутствие SCRIPT ERROR/Parse Error/runtime errors и ноль failures. Любой ненулевой exit, пустой прогон или ошибка в логе — провал. Указать количество запущенных файлов, проверок, failures и skips; не менять игровой runner в рамках миграции;
- импорт: `"$GODOT_BIN" --headless --editor --quit --path .`; сохранить полный лог и код выхода, проверить SCRIPT ERROR/Parse Error; grep без совпадений сам по себе не доказывает успех;
- смоук: игра запускается из лобби, раунд играется, квест тикает,
  баланс общий, возврат в лобби работает.

## Правила проекта (не нарушать)

- Никаких хардкодов текста (только Translations.tr_key) и
  тюнинг-параметров (только configs/*.json) — docs/CODEX_PROJECT_REFERENCE.md §9.
- Ядро (`core/`, `scenes/`, `main.gd`) при добавлении игры НЕ трогается.
  Если без правки ядра не обойтись — это дыра в контракте: остановись и
  обсуди с пользователем, потом внеси правку и обнови GAME_INTEGRATION.md.
- Не коммитить без явного одобрения пользователя.
- Референс-ассеты из APK в репозиторий не копировать.
