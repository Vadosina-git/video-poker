Сначала прочитай проектные AGENTS.md/CLAUDE.md, `../GODOT_CONVENTIONS.md`, `docs/CODEX.md` и `docs/CODEX_PLUGIN_PARITY.md`. Сопоставление среды - `~/.codex/migration/bridge.md`. Снимки исходных процедур ниже сохранены полностью; поправки этого Codex-входа и правила проекта имеют приоритет.

Прочитай `references/code-review.md` целиком и применимые AGENTS/CLAUDE измененных областей. Для PR получи состояние, описание, diff и прежние комментарии через фактически доступный GitHub connector или gh. Прямая просьба перепроверить draft/уже проверенный PR важнее старого фильтра на пропуск; для локального diff PR не обязателен.

Сохрани независимые проходы: проектные правила, ошибки нового кода, проверка кандидатов на ложные срабатывания. Делегируй реальными collaboration tools только при разрешении и в пределах трех дочерних исполнителей; остальные проходы проведи последовательно. Старое предположение, что все tools безошибочны, не применять: проверь результаты и пропуски. Не выдавай доступ к GitHub за разрешение оставлять комментарий: без поручения на публикацию findings идут в чат. `--comment` означает запрос публикации лишь когда его передал владелец для этой задачи. При отсутствии inline tool подготовь точные комментарии и назови ограничение, не выдумывай отправку.

Особое внимание предметным ограничениям: выплаты из paytables/документа, round_finished и начисления без дублей, совместимость save, локальный и remote config, локализация en/ru/es и общие раскладки single/multi/spin. Проверку веди в запрошенном охвате, не расширяй в отдельный аудит всей игры. Существенное замечание подкрепи местом, воспроизводимым сценарием и влиянием на игрока. Ноль findings - отсутствие подтвержденных проблем только в проверенном охвате.
