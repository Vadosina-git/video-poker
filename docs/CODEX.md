## Точки запуска и проверка

В терминале из корня проекта: `codex`. Движок — установленный Godot 4.6;
На миграции read-only `--version` вернул `4.6.1.stable.official.14d19694e`;
проверить точный patch командой `"$GODOT_BIN" --version`, не менять версию миграцией.
Путь задаётся окружением; локально обнаружен стандартный macOS app bundle:

```bash
export GODOT_BIN="${GODOT_BIN:-/Applications/Godot.app/Contents/MacOS/Godot}"
"$GODOT_BIN" --version
# Прогреть/import class_name cache; это пишет .godot/, не read-only проверка
"$GODOT_BIN" --headless --editor --quit --path .
# Игровые проверки
GODOT_BIN="$GODOT_BIN" ./tests/run_all.sh
# Визуальный локальный запуск
"$GODOT_BIN" --path .
```

Стартовая сцена: `scenes/splash.tscn`. Команды здесь описаны, игровые прогоны,
импорт и сборки при миграции не исполнялись. Проверки миграции — в
`.codex/project-migration.json`: hash originals, файлы/ссылки и покрытие процедур.
Тестовый результат фиксировать с кодом выхода, количеством проверок, failures
и skips; код 0 без проверок не успех. UI дополнительно проверять снимком
через доступный browser/computer инструмент или Godot capture и view_image.

Существующий tests/run_all.sh сверяет текстовые маркеры и подавляет exit code Godot. Поэтому дополнительно сохранять реальный код каждого тестового процесса и проверять ошибки парсинга/непустое число assertions; сам скрипт миграцией не менялся.

## Разрешения и процедуры

Не переносить .claude/settings*.json, auth, allowlists, модель или bypassPermissions
в Codex. Хуки требуют штатного доверия /hooks; наличие конфигурации не доказывает
исполнение. Использовать только доступные инструменты текущей сессии.
Секреты из .env, .p8, JSON credentials и keystore не печатать и не коммитить.
Миграция разрешает документацию/адаптеры, не build/export/upload, не store
submit, не production, не создание репозитория или коммит. По отдельной задаче
следовать указанному объёму и профильным release docs; наличие скрипта не даёт
разрешения запускать внешние действия. Новые зависимости без согласования не ставить.

Если задача требует делегирования, использовать реальные collaboration tools:
spawn_agent, send_message, followup_task и wait_agent, когда они доступны и
делегирование разрешено. Передать роль, входы, границы и путь результата;
при отсутствии инструментов выполнить последовательно. Нет отдельного Workflow SDK.
Поиск ограничивать текущим проектом; не сканировать соседей или архивы.

Локальная процедура `$add-new-game` / `/skills`: `.agents/skills/add-new-game/SKILL.md`, полная версия `.codex/workflows/add-new-game.md`. Зависимость `$rip-godot` — `~/.agents/skills/rip-godot/SKILL.md`; читать её и bridge перед выполнением. Референс вне репозитория, а не новый отдельный проект.

## Локальные метаданные аудита

`.codex/project-migration.json`, приватные отчеты, хеши и архивы памяти
хранятся только на машине владельца и не входят в репозиторий. Они необязательны
для запуска Codex из клона. Рабочие инструкции находятся в `AGENTS.md`,
этом руководстве и карте архитектуры; отсутствие локального аудита не блокирует работу.
